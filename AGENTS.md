# AGENTS.md

## Overview

Dotfiles repo plus `dot`, a small Rust CLI that installs them. Scope is
deliberately narrow: clone a repo, link dots, unlink them, update itself.

- A **dot** is a folder: `dot/<name>/config/` → `~/.config/<name>/` (folder symlink).
- State lives in sqlite at `~/.local/share/dot/dot.db`; the clone lives in
  `~/.local/share/dot/repo`; displaced directories go to
  `~/.local/share/dot/backups/<epoch>/`.
- The only thing written outside `~/.local` is the symlink in `~/.config`.
- Everything in this repo is written in English: code, output, docs.

## Structure

```
dotfiles/
├── dot/                    # one folder per dot
│   └── nvim/
│       ├── metadata.yml    # optional: description + hooks.install
│       ├── config/         # → ~/.config/nvim (symlinked as a folder)
│       └── scripts/        # hook scripts, never linked
├── src/                    # the `dot` crate
├── tests/dot.rs            # scan + db tests
├── Cargo.toml
├── rustfmt.toml            # hard tabs, width 100
├── install.sh              # installs the binary into $PREFIX/bin (default /usr/local)
└── uninstall.sh            # unlinks, removes the binary and ~/.local/share/dot
```

## CLI

| Command | What it does |
|---|---|
| `dot init <repo>` | clones a git repo into `~/.local/share/dot/repo` (or adopts a local path) and stores it in sqlite |
| `dot list` | docker-style columnar output (uppercase headers, no borders): name, state (`installed`/`not installed`/`foreign`/`conflict`), description. `-q` prints only names |
| `dot install <dot>\|--all` | pulls the repo first (so an installed dot is updated to the latest commit), then links, backs up a real directory in the way, runs `hooks.install`, records in sqlite. A failed pull is a warning, not an error |
| `dot uninstall <dot>\|--all` | removes only links pointing into this repo, deletes the record |
| `dot update` | `git pull --ff-only` + `cargo build --release` + replaces the running binary |

No global flags. Each command does one thing.

## Crate

```
src/
├── main.rs        # dispatch
├── cli.rs         # clap: 5 commands
├── app.rs         # App::load (db + repo + scan), App::select
├── db.rs          # sqlite: meta (repo) + dots (install history)
├── dot.rs         # Dot, metadata.yml, repo scan, name validation
├── repo.rs        # git clone/pull
├── binary.rs      # rebuild + self-replace of the running binary
├── fsutil.rs      # symlink / copy_tree / remove primitives
├── installer.rs   # state/link/unlink/backup policy, returns outcomes (no printing)
├── hooks.rs       # sh -c from the dot directory
├── paths.rs       # ~/.local/share/dot, ~/.config, backups
└── commands/      # init, list, install, uninstall, update
```

Design rules:

- **The filesystem is the truth** for "is it installed?" (a symlink into the repo).
  sqlite only stores the repo location and the install history.
- Everything `dot` writes goes to `~/.local/share/dot`; never a loose file in
  `~/.config` (only symlinks).
- `installer.rs` is the only module that creates or removes symlinks, and it
  returns outcomes instead of printing; commands print.
- Modules below `commands/` are silent: only the CLI layer writes to stdout.
- Paths are injected (`Paths`), never read from the environment inside logic.
- User configuration is never deleted: a directory in the way is moved to `backups/`.

## metadata.yml

Optional. Parsed with `deny_unknown_fields`, so a typo is an error (reported as a
warning by `dot list`, because one broken dot must not break the whole listing).

```yaml
description: Neovim
hooks:
  install: ./scripts/molten-venv.sh   # cwd = dot/nvim
```

## Nvim

Package: `dot/nvim/config/` → `~/.config/nvim/`

Plugin manager: [lazy.nvim](https://github.com/folke/lazy.nvim) (auto-bootstrapped).

### Adding a plugin

1. Create `lua/plugins/<plugin>.lua`
2. Return the lazy.nvim spec
3. Keep non-trivial logic in `lua/<domain>/` and let the spec wire it up

### Theme

[Rosé Pine](https://github.com/rose-pine/neovim) dark (`main`), in `plugins/colorscheme.lua`.

### Plugin conventions

- Plugin keybindings live in the plugin spec (`keys` or `config`); `config/` only
  holds editor-wide settings
- One plugin per file; specs stay declarative
- Non-trivial logic lives in its own module and is required from the spec

### File explorer

Netrw is disabled; `snacks.explorer` replaces it.

- `-` opens the explorer at the `cwd`, focuses it when open and closes it when focused; `<Esc>` or `q` closes it
- `<CR>`/`l` opens, `h` collapses, `<BS>` goes up, `H` hidden, `I` gitignored, `P` preview
- `a` add (`/` suffix = directory), `r` rename, `d` delete (trash), `c` copy,
  `m` move, `y`+`p` yank/paste paths
- Shows git status and diagnostics per entry (`]g`/`[g`, `]d`/`[d`)

### Terminals

`snacks.terminal` is the only implementation.

- `<leader>t` (n/t) toggles a bottom split (`count` for more terminals)
- `<Esc><Esc>` leaves terminal mode
- `snacks_terminal` buffers are excluded from lualine

### AI agent (pi.nvim)

Bridge to [pi](https://pi.dev) (`kurochenko/pi.nvim`). Loads on `VeryLazy`; `pi`
must be in `PATH`.

| Key | Mode | Action |
|-----|------|--------|
| `<leader>pt` | n, t | Open / focus / close the panel |
| `<C-h>` | n, t | Back to the code, panel stays open |
| `<leader>pa` | n, v | Ask pi about the code / selection |
| `<leader>px` | n, v | Action picker (explain, review, fix, test, …) |
| `<leader>pp` | n, v | Send context directly |
| `<leader>pq` | n | Abort the current operation |

Placeholders: `@this`, `@buffer`, `@buffers`, `@visible`, `@diagnostics`,
`@quickfix`, `@diff`. Also `:Pi toggle|ask|prompt|select|abort`.

### Data science (molten)

Needs a venv with `pynvim` + `jupyter`. `dot install nvim` creates it at
`~/.local/share/nvim/molten-venv` through `dot/nvim/scripts/molten-venv.sh`
(referenced by `vim.g.python3_host_prog`). In a markdown buffer:
`:MoltenInit python3`, then the `<leader>r*` keymaps.

## Conventions

- **Indentation**: tabs, width 2 (`.editorconfig`, `rustfmt.toml`)
- **Language**: English only, in code, output and docs
- **Comments**: none
- **Git**: no `.DS_Store`, no `*.local`, no `target/`
- **Secrets**: never in the repo; hooks read them from env vars

## Maintenance

```bash
dot update        # pull + rebuild + self-replace
dot list          # state of every dot
cargo test
```

Inside nvim: `:Lazy sync` (rewrites `lazy-lock.json`), `:TSUpdate`, `:Mason`.
Commit `lazy-lock.json` changes so every machine lands on the same revisions.
